3D ULPIN Generation and Vertical Property Mapping System — V8.1
==============================================================

V8.1 preserves the V7.3 Flask pages, dashboard, CSV-based prototype property workflow,
AI extraction interface, polygon processing, and GIS + 3D integration, while replacing
the remote GeoBase ONNX model with the supplied trained PyTorch checkpoint.

BOUNDARY DISPLAY CORRECTION (V8.1)
---------------------------------
The 3D prototype outline is now drawn coincident with the AI footprint polygon. The
previous 1.5 m outward expansion has been removed because it made outlines appear
larger than the detected roof. This outline is not a surveyed/legal parcel boundary.


MODEL
-----
Architecture: segmentation_models_pytorch.Unet(
  encoder_name="resnet34", encoder_weights=None, in_channels=3,
  classes=1, activation=None
)
Checkpoint: models/unet_resnet34_whu_best.pth
Checkpoint format: dictionary containing model_state_dict, optimizer_state_dict,
epoch, val_loss, and val_dice. The inference code loads model_state_dict strictly.
Input: RGB, 512 x 512 tiles, float [0,1], ImageNet mean/std normalization.
Output: one-channel logits -> sigmoid probabilities -> threshold (default 0.50).
The model is cached in process memory after its first load. CPU is supported;
CUDA is selected only when PyTorch reports it available.

WINDOWS SETUP
-------------
1. Extract 3D_ULPIN_Flask_V8.zip to a writable folder, for example C:\Projects\.
2. Open the extracted 3d_ulpin_flask_v7_3 folder in VS Code or PowerShell.
3. Create a virtual environment:
     py -3.11 -m venv .venv
4. Activate it:
     .venv\Scripts\activate
5. Upgrade pip and install dependencies:
     python -m pip install --upgrade pip
     python -m pip install -r requirements.txt
   PyTorch installation can vary by Python/Windows setup. If pip reports that no
   compatible torch wheel exists, install a supported Python version (Python 3.10
   or 3.11 recommended) and install PyTorch from https://pytorch.org/get-started/locally/
   before rerunning the requirements command.
6. Start the Flask app:
     python app.py
7. Open:
     http://127.0.0.1:5001/ai-extraction
   Dashboard: http://127.0.0.1:5001/
   GIS + 3D: http://127.0.0.1:5001/gis-3d
   Version endpoint: http://127.0.0.1:5001/version

TROUBLESHOOTING
---------------
- Missing checkpoint: confirm models\unet_resnet34_whu_best.pth exists next to app.py
  under the models folder. Do not rename it unless MODEL_PATH in app.py is updated.
- Architecture/key mismatch: ensure this is the matching U-Net with ResNet34 encoder,
  one input/output channel configuration as specified, and the supplied checkpoint.
  The loader uses strict=True to avoid silently accepting a mismatched checkpoint.
- segmentation_models_pytorch / timm import errors: run
     python -m pip install --upgrade segmentation-models-pytorch timm
- Torch install errors: use a supported 64-bit Python version and the official PyTorch
  installation selector; CPU-only PyTorch is sufficient for Intel Iris systems.
- Port 5001 busy: close the other process using the port or change app.run port in app.py.
- Large/invalid images: accepted formats JPG/JPEG/PNG/WEBP; upload max is 25 MB and
  image dimensions are limited by the app's existing safeguards.
- Inference errors: read the Flask terminal traceback and confirm sufficient RAM.

IMPORTANT LIMITATIONS
--------------------
- This is a student-project prototype. Generated identifiers are prototype IDs, not
  official government-issued ULPINs. A detected roof/building is not necessarily one
  legal property.
- Polygon vertices are image-pixel coordinates unless valid georeferencing is supplied.
  The V7.3-derived 3D prototype uses synthetic/local coordinate assumptions; it does
  not establish real geographic coordinates or official parcel boundaries.
- Any scale, parcel boundary, height, floor count, or location generated by prototype
  rules must not be treated as surveyed/legal data. GeoJSON with real geographic
  coordinates is not inferred from an ordinary image.
- Model performance may vary with sensor, resolution, region, season, roof type, and
  imagery distribution. Review all masks and polygons manually.
- No training dataset is needed at inference time.

TEST STATUS
-----------
The source was updated to use the supplied checkpoint format and intended architecture.
The V8.1 boundary-display change removes the artificial outward parcel expansion.
Syntax/import checks and end-to-end model inference depend on the target machine's
installed PyTorch and segmentation-models-pytorch versions. No claim of verified
end-to-end inference or visual accuracy is made in this package.


DEMO LOGIN (V8.2)
-----------------
The application now displays a login page before allowing access to application routes.
Demo accounts are listed in users.csv (columns: uid,password). You may add rows using the same format.
Sample accounts: USER001 / Demo@101 and USER002 / Demo@102.
Use the Logout option by visiting /logout. This CSV uses plain-text passwords for a local demonstration only; do not expose it on a public server.
For deployment beyond a controlled demo, use password hashing, a strong FLASK_SECRET_KEY, and appropriate access controls.


DASHBOARD INPUT UPDATE (V8.3)
-----------------------------
The dashboard no longer provides CSV/Excel upload or dataset-generation controls.
It loads the bundled sample_data.csv internally for the demonstration dashboard.
For user-provided input, use the AI Building Footprint page and upload an image
(JPG/JPEG/PNG/WEBP). The users.csv file remains only for demo login credentials.


LOGIN SESSION UPDATE
--------------------
Login is required before accessing application pages. Credentials are checked against
users.csv (uid,password). The session is a browser-session cookie (no Remember Me /
persistent 30-day session). Close the browser session or use Logout to end access.
The Logout links are available in the application navigation. For production use,
set a strong FLASK_SECRET_KEY and store password hashes instead of plain-text passwords.
